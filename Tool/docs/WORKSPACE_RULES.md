# Seep 工作空间任务隔离与目录管理规范 (Workspace Rules)

本规范为 **Seep 逆向与攻防工程平台** 的最高级别目录管理铁律，由主人制定并由小π严格执行。

---

## 核心准则：一任务一目录，零根目录污染

所有在此工作空间（`seep/`）开展的新任务（无论逆向分析、漏洞挖掘、POC复现、补丁研发或解包审计），必须严格遵守以下规则：

### 1. 新任务强制新建独立文件夹
- **规则**：接到主人下达的任何新任务时，**首先**必须在根目录下创建以任务/目标命名的专属子文件夹（例如 `tasks/<目标名>/` 或根目录专属 `<目标名>/`，如 `xyplorer/`、`mumu/`、`Hills/`）。
- **禁止行为**：严禁在 `seep/` 根目录下直接进行临时文件的创建、提取、解压或运行输出。

### 2. 全生命周期数据闭环隔离
- **过程产物归位**：
  - 分析日志（*.log）
  - 临时抓取与截图（*.png, *.jpg）
  - 中间逆向提取文本（*.txt, *.csv, *.json）
  - 汇编/机器码/内存 Dump（*.bin, *.dmp, *.id*）
  - 编写的补丁代码与构建脚本（*.c, *.py, *.ps1, *.dll, *.exe）
- 以上所有产物**必须 100% 存放于对应任务专属文件夹内**，绝不允许溢出到根目录。

### 3. 命令执行上下文规范
- 在运行 PowerShell、Python、Radare2、Apktool 或编译器时，必须显式切换到对应任务文件夹上下文执行（即先 `cd <任务文件夹>`），确保工作进程生成的临时日志与派生产物直接就地留存。

### 4. 根目录资产白名单
`seep/` 根目录仅允许保留以下系统级公共组件，严禁堆放其他个人或任务文件：
- `seep_mcp_server.py` / `test_seep_mcp.py` / `run_seep_mcp.bat`：Seep 核心 MCP 服务套件
- `Tool/`：【专属工具库】所有全局逆向工具链、分析套件及通用辅助脚本（包括 `Tool/scripts/`）统一存放在此
- `open-reverselab/`：底层知识库与核心支持框架
- 各任务独立业务文件夹（如 `Hills/`, `mumu/`, `xyplorer/` 等）
- `WORKSPACE_RULES.md`：本规范文件

---

## 交付物 vs 工作区：`Tool/audits/` 与 `lab/` 的分流

一次审计/逆向任务收尾时，产物必须按「**能否入库**」分成两处，不得混放：

| 目录 | 放什么 | 版本库 |
|---|---|---|
| `Tool/audits/<目标>/` | **已整理的交付物**：报告、方法论、只读基线数据、带单元测试的检查工具 | ✅ 入库 |
| `lab/<目标>/` | **工作区**：真实样本、补丁二进制、自签私钥、签名许可、一次性探针 | ❌ `.gitignore` 排除 |

### 1. `Tool/audits/` 结构约定
```
Tool/audits/<目标>/
├─ README.md          索引：目标是什么、有哪些交付物、工作产物在哪
└─ <平台>/            按平台分目录（windows / macos / ...）
   ├─ REPORT.md / METHODOLOGY.md / BASELINE-*.md
   └─ tools/ + tests/ （可复用检查工具及其单元测试）
```
- 同一目标的多个平台共用一个 `<目标>/` 目录，**不按平台再拆顶层目录**。
- 历史阶段的只读基线保留为 `BASELINE-*.md`，并加横幅声明「已被正式报告取代」，避免与最终结论冲突。

### 2. `lab/<目标>/` 工作区约定
```
lab/<目标>/
├─ samples/   pristine 样本（只读，永不原地修改）
├─ out/       补丁产物、自签 license.* / mint_keys.json
├─ probes/    一次性探针与取证脚本
├─ evidence/  日志与观测记录
└─ tools/     可复用脚本
```
- 真实样本、补丁二进制、任何私钥/签名许可**只能**留在这里，并确保被 `.gitignore` 命中。
- 还原凭据（原始备份路径、MD5、恢复命令）必须写进 `REPORT.md`，保证可回滚。

### 3. 案例包（PoC 与方法论）
- `Tool/cases/<案例>/`：可发布的 PoC、签发/复现脚本与文档；入库。
- 案例包与 `Tool/audits/` 分工：前者回答「怎么做、协议是什么」，后者回答「这次实测发现了什么」。
- 交叉引用用相对路径双向指路，避免同一事实散落多处。
