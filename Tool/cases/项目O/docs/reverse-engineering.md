# 项目O Electron/asar 授权流审计 —— 薄转发层 + V8 字节码信任路径 + 数据层旁路（CWE-602）

> 目标：`项目O` 桌面下载器（Electron 主进程 + sidecar 下载引擎）
> 平台：macOS arm64 实测；Windows 同架构姊妹版（`<目标版本>`）
> 交付产物：授权链取证报告 + 公钥替换旁路复现步骤（本地闭环）
> 结论（2026-10-10 CDP 实测修订）：**判定权确实在本地（CWE-602 成立），但"数据层伪造即放行"在 0.12.5 实测不成立——伪造 license.json 被验签整体否决（`unactivated`）；可复现旁路 = 替换 jsc 内嵌公钥 + 自签（详见 §3 修订与内部工作区证据）。**

## 0. 为什么这是新的范式

项目A–N 全部是原生二进制授权流：PE 节区 / .NET IL / JVM 字节码 / Qt5 C++ / Rust。
本案例的授权判定点在 **打包产物层**：

```
asar 归档（zip-like）
  └── dist-electron/main/
        ├── license/*.js        ← 25 个模块，全部一行转发
        ├── license-core.js     ← 4 行引导
        └── license-core.jsc    ← bytenode 编译的 V8 字节码（真实逻辑）
```

审计不需要脱壳器、不需要 AOB、不需要 IDA：`asar extract` + `strings` + 运行时数据取证，
分钟级完成。这就是"脚本层授权流审计"范式。

## 1. 信任链分层（实测）

### 1.1 薄转发层

`asar/dist-electron/main/license/` 下 25 个 `.js` 全部是同一形态：

```js
module.exports = require('../license-core')["activator"]
```

模块清单：`activator api clock-store consent-gate crypto device-report epoch-watch
expiry-latch fingerprint gate hb-secret heartbeat-policy heartbeat-send ipc keys
persist-util server-notice server-verdict session-clock storage ticker transport
types verifier`

**审计意义**：转发层暴露了完整的授权架构拓扑（模块名即功能名），是字节码
反编译前的免费信息源。

### 1.2 引导层

```js
// auto-generated by scripts/bundle-trust-path.mjs; loads the compiled trust path
require('bytenode')
module.exports = require('./license-core.jsc')
```

### 1.3 字节码层

`license-core.jsc`（bytenode / V8 bytecode）。源码不可见，但**明文字符串保留**：
路由串、环境变量名、错误日志串、模块引用串全部可提取。用字符串取证即可重建
10 段链路（见 §2）。

## 2. 字节码内 10 段授权链路（字符串重建）

| # | 段 | 模块符号 | 行为 |
|---|----|---------|------|
| 1 | 指纹 | `fingerprint` | 生成 16 位 hex deviceId |
| 2 | 密钥 | `keys` / `crypto` | Ed25519 验签，公钥内嵌（@noble/curves） |
| 3 | 激活 | `activator` | POST `/v1/activate` · `/v1/deactivate` · `/v1/devices?key=` |
| 4 | 验证 | `verifier` | 本地验签 → 布尔判定 |
| 5 | 时钟锚定 | `clock-store` + `session-clock` + `epoch-watch` | 高水位（hwm）夹住时间回拨 |
| 6 | 过期锁存 | `expiry-latch` | 到期状态单向闩，只进不退 |
| 7 | 心跳 | `heartbeat-policy` + `heartbeat-send` + `hb-secret` | POST `/v1/heartbeat`；断网降级本地判定 |
| 8 | 服务端裁决 | `server-verdict` / `server-notice` | `/v1/diag` 上报与裁决回执 |
| 9 | 持久化 | `storage` / `persist-util` | license.json + hwm + 版本策略缓存 |
| 10 | 门控 | `gate` / `consent-gate` / `ticker` | 判定结果对 UI 的放行 |

端点不硬编码，走环境变量：

```
LICENSE_API_URL          主 API 基址
LICENSE_EPOCH_PATH       时间高水位文件路径
LICENSE_EPOCH_TIMEOUT_MS epoch 超时窗口
```

相对路由（jsc 字符串原文，主机名以 `<product>` 代）：

```
/v1/activate  /v1/deactivate  /v1/devices?key=  /v1/heartbeat  /v1/diag
/api/v1/<product>/commerce/handoffs
/api/v1/<product>/license-epoch
```

版本策略（明文 JS，非授权路径）：
`https://github.com/<vendor>/<product>-desktop/releases/latest/download/version-policy.json`

## 3. 判定模型与攻击面

**CWE-602 判定**：权威归属 = **本地布尔**。
心跳/服务端裁决是增强路径，不是权威——断网后 `heartbeat-policy` 超时，
`verifier` 仍用内嵌公钥对本地 license 数据做离线验签。判定权始终留在被审计方手里。

**数据层攻击面**（应用数据目录）：

| 文件 | 作用 | 实测旁路要求 |
|------|------|---------|
| `license.json` | 激活成功后的**明文缓存**（非权威） | 单独重写**不放行**——gate 验签失败即 `unactivated`（0.12.5 实测） |
| `license.bin` | **主授权存储**（加密，915B，熵 7.81） | 判决的真正输入；缺失时 gate 回退读 license.json 验签链 |
| `license-hwm.json` | 时钟高水位 | 须与新授权数据时间一致，否则被 epoch-watch 夹住 |
| clock-store 数据 | 会话时钟锚 | 与新 hwm 一致 |
| `license.bin.bak` | 原始授权备份 | 对照实验基线（还原后判决 `blocked: expired`，证明签名合法路径仍通） |

**时钟锚定三件套的对抗**：
1. 只改系统时间 → `epoch-watch` 检测到 hwm < 当前时间，拒绝并回写。
2. 改系统时间 + 同步抬高 hwm → 理论放行，但**前置条件**是数据先过验签（0.12.5 未复现单独放行）。
3. `expiry-latch` 一旦锁存到期 → 需同时清闩（数据层可清，非硬件绑定）。

**实测修订（2026-10-10，CDP 直测门控）**：

| 实验 | license.json | license.bin | 门控判定 |
|---|---|---|---|
| A | 伪造补丁态 | 缺失 | `unactivated` |
| B | 伪造补丁态（mode=offline） | 缺失 | `unactivated` |
| C | 伪造补丁态 | 还原原厂件 | `blocked: expired` |

**约束（修订）**：Ed25519 公钥内嵌字节码。任意伪造 license.json 数据**必然验签失败**，
"断网降级放行"只对**签名合法**的数据开放。jsc 字符串表中的
`clearedVerdictPatch`（反补丁标记）+ `require_server_verdict` 表明数据层补丁会被检测。
因此可复现旁路 = **替换 jsc 内嵌公钥（bytecode patch）→ 自签授权数据**，
而非纯数据层重写。公钥提取 = 待办（V8 字节码反编译，难度高于原生 IDA 路径；
字符串表捞到的 64-hex 常量经验证均为域参数，非厂商公钥）。

## 4. 复现步骤（macOS arm64）

```bash
# 1) 解包
npx @electron/asar extract <app>.app/Contents/Resources/app.asar asar/

# 2) 确认信任链（25 个模块全部单行转发）
grep -r "license-core" asar/dist-electron/main/license/

# 3) 字节码字符串取证
strings asar/dist-electron/main/license-core.jsc | grep -E '/v1/|LICENSE_'

# 4) 运行时数据取证
ls <app data>/   # license.json · license-hwm.json · *.db

# 5) 门控直测（CDP，0.12.5 实测方法；主进程 --inspect 被 fuse 禁用）
#    open -a <app> --args --remote-debugging-port=9333
#    window.api.license.getStatus()  ← 判决入口
#
# 6) 旁路（本地闭环，0.12.5 实测结论）
#    纯数据层重写 license.json/hwm → 验签失败，gate 判 unactivated，不放行
#    可复现旁路 = patch jsc 内嵌公钥 + 自签授权数据（详见 §3 实测修订）

完整性基线：`app.asar` SHA256 `44b529eeb37f01a8da36427ef427366efc542c95b92eb317f83c3c00258dc659`（6,740,911 B）。

## 5. 防护评估

| 防护 | 强度 | 说明 |
|------|------|------|
| bytenode 字节码 | 中 | 隐藏源码，但字符串全保留；V8 jsc 反编译工具链成熟 |
| 时间高水位 | 中 | 防回拨有效，但数据层可写 |
| 单向过期闩 | 弱 | 纯软件状态，数据层可清 |
| license.bin 加密主存储 | 中 | 数据层补丁不触及；但同进程可读 |
| 反补丁标记 `clearedVerdictPatch` | 中 | 数据层补丁会被检测/清除 |
| Ed25519 验签 | 强（未破） | 公钥内嵌可提取，提取前无法自签 |
| 端点环境变量化 | 中 | 反混淆有效，但判定不依赖端点 |
| **降级本地判定** | **致命** | 把最终判定权留给被审计方 = CWE-602 根因 |

**一句话（0.12.5 实测修订）**：这个授权系统的"最坚固环节"（Ed25519 验签 + 加密
license.bin）在纯数据层攻击面前守住了——伪造数据判 `unactivated`，原厂过期件判
`expired`；判定权虽在本地（CWE-602 成立），但**改判的前提是先过验签**，
旁路必须下沉到字节码层（公钥替换 + 自签）。
